## Migration

Three migrations, in this order (the order matters — see below):

1. **`drizzle/0027_punch_unified_renumber.sql`** — custom (`npx drizzle-kit generate --custom --name punch_unified_renumber`). R-117: in every project where a Site punch item shares its number with an ITP item, the Site items are renumbered after the project's highest ITP number (HLT-026: site P-01…P-03 → P-06…P-08), in their order, and placed after the ITP items — two steps through a temporary `TMP-<id>` number so the old unique key is never hit. A project without a clash is left alone (re-runnable). Then Site items without a category become `B`, ITP items without an owner party become `keystone`.
2. **`drizzle/0028_new_frank_castle.sql`** — generated (`npm run db:generate`): creates `itp_plan_systems` (PK `(plan_id, position)`, unique `(plan_id, name)`, FK → `itp_plans` cascade) and `site_conflict_arbitrations` (unique `(project_id, conflict_key)`, FK → `projects` cascade, → `persons`); drops `punch_items_project_id_register_number_unique` and adds `punch_items_project_id_number_unique`.
3. **`drizzle/0029_itp_plan_systems_backfill.sql`** — custom (`--name itp_plan_systems_backfill`). R-057: every existing plan without frozen systems gets the current ITP systems of its machine type (AUTRE's when the type has none), in their order, a duplicated name kept once; `ON CONFLICT DO NOTHING`, plans that already have rows are skipped (re-runnable).

Plus `drizzle/meta/0027…0029_snapshot.json` and `_journal.json`. No existing migration was edited. R-118 and R-122 / R-032 need no schema change.
